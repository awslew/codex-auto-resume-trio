## 0. 总览

| 供应商 | 计费类型 | 官方数据源 | 状态 | 代理 |
|---|---|---|---|---|
| DeepSeek 官网 | balance（按量余额） | GET https://api.deepseek.com/user/balance | ✅ 官方源可用 | 直连（域内） |

| Codex (ChatGPT) | subscription（订阅额度） | GET https://chatgpt.com/backend-api/wham/usage | ✅ 官方源可用（走 ~/.codex/auth.json 登录态） | Clash 127.0.0.1:7897 |

## 1. DeepSeek 官网 API（余额）

- key 来源：DeepSeek 官网控制台创建的 key。明文见 config.yaml，本文件不重复。
- endpoint：`GET https://api.deepseek.com/user/balance`
- 认证：`Authorization: Bearer <key>`；**直连**，无需代理。
- 实测返回（2026-08-04，数值为脱敏样例）：
```json
{"is_available":true,"balance_infos":[{"currency":"CNY","total_balance":"12.34","granted_balance":"0.00","topped_up_balance":"12.34"}]}
```
- 解析要点：取 `balance_infos[0]`；`total_balance` 是**字符串**（转 float）；`is_available=false` → 视为账户不可用；`granted_balance`=赠送、`topped_up_balance`=充值。
- 展示：余额 ¥12.34。单位 CNY。API 不提供"已用量"，used 置 None。

## 2. OpenRouter（credits）

- key 来源：OpenRouter 官网控制台创建的 key。明文见 config.yaml。
- ⚠️ 历史遗留的旧 key（`sk-or-v1-xxxx...`）已失效（返回 401 User not found），**不可用**，勿用。
- endpoint：`GET https://openrouter.ai/api/v1/credits`（路径含 /v1）
- 认证：`Authorization: Bearer <key>`；**必须走 Clash 代理 127.0.0.1:7897**。
- 实测返回（2026-08-04，数值为脱敏样例）：
```json
{"data":{"total_credits":10.0,"total_usage":7.5}}
```
- 解析要点：`data.total_credits`=总量(10 USD)；`data.total_usage`=已用(7.5 USD)；**余额 = total_credits - total_usage**（≈$2.50）。`data.limit` 无（/v1/credits 无此字段；/v1/auth/key 里 limit=null）。
- 展示：余额 $2.50 / 已用 $7.50 / 总量 $10.00。单位 USD。

## 3. OpenCode Go（订阅额度）— 最高风险

- key 来源：OpenCode Go 官网创建的 key。明文见 config.yaml。
- key 有效性：已实测 `GET https://opencode.ai/zen/go/v1/models`（Bearer 该 key）返回 200 模型列表 → **key 有效**，但只对推理接口有效。
- **官方用量查询 API：不存在**。证据：
  - 官方文档 https://opencode.ai/docs/go/ 明示 "You can track your current usage in the console."（用量只能在控制台网页看）。
  - GitHub issue anomalyco/opencode#23513「Does my OpenCode Go subscription bill via the REST API?」→ 无 REST 用量接口。
  - 源码（DeepWiki 索引 packages/console/...）：用量页 = `workspace/[id]/usage`，浏览器登录态(session)认证，非 API key 可触达。
- **限额（官方文档，按美元价值计）**：5小时窗 $12 / 周窗 $30 / 月窗 $60。
- **唯一官方源 = 控制台登录页**：`https://opencode.ai/workspace/<workspaceId>/go`（用户实测确认的正式地址；示例：`https://opencode.ai/workspace/<你的workspaceId>/go`）。注：不是 app.opencode.ai/.../usage。
- **方案（易卡点1 路线 b）**：用户从浏览器登录 app.opencode.ai 后复制 cookie 填 `config.yaml` 的 `opencode_go.cookie`，并填 `usage_url`（含自己的 workspaceId）。`opencode_go.py` 用 requests 带 cookie 抓官方用量页并解析各窗口已用金额。
- **硬约束**：解析失败 / 未配置 cookie / 页面结构变化 → 一律返回 `source_status='不可用'`。**禁止硬编码、禁止用本地端口/日志/路由数据推算**。本次交付默认未配 cookie → 卡片显示「官方数据源不可用」，如实。

## 3.5 Codex（ChatGPT 订阅额度）— 2026-08-11 新增

- 背景：用户新增 GPT（Codex CLI）使用，需观测剩余额度。本机 `~/.codex/auth.json` 为 ChatGPT OAuth 登录态（有 tokens.access_token / refresh_token / account_id，无 API key）。
  - 官方用量 API 不存在公开文档，但 ChatGPT 后端实际提供：`GET https://chatgpt.com/backend-api/wham/usage`。
  - 认证：`Authorization: Bearer <auth.json 的 access_token>` + `ChatGPT-Account-Id: <account_id>` 头。
  - 实测返回（2026-08-11）：`rate_limit.primary_window={used_percent:0, limit_window_seconds:604800(7天), reset_after_seconds:…, reset_at}`；`secondary_window`、`additional_rate_limits` 为 null；`credits.has_credits=false`；`spend_control.individual_limit=null`。（返回中的具体数值与本机账号信息均不入库，此处只保留字段结构。）
  - ⚠️ 不是 `/backend-api/usage`（对当前账户返回 404）。实现复刻自 GitHub 高星项目 **steipete/CodexBar(19.9k★)** 的 `CodexOAuthUsageFetcher.swift`（已做源码安全审计，仅向 chatgpt.com 官方域名发 token）。
- 窗口解析：`primary_window` / `secondary_window` → `WindowUsage(label=按 limit_window_seconds 映射, percent=used_percent, reset_in_sec=reset_after_seconds)`；`additional_rate_limits[]` 里的主窗口 → 专项限额窗口；`spend_control.individual_limit` / 顶层 `individual_limit` → "消费上限"窗口（limit/used/percent）。
- 认证数据源 = `~/.codex/auth.json`（config.yaml 的 `codex.auth_path` 可覆盖）。**只读，绝不写回**。
- 网络：chatgpt.com 走 Clash 代理间歇性超时（实测成功率 ~40-80%），provider 内重试 3 次；失败由调度器保留旧数据标 refresh_failed。
- 硬约束：401/403 → 不可用（提示重登 codex）；无 auth.json → 不可用；绝不硬编码额度。

## 4. 统一数据模型（契约 · 所有模块复用）

文件：`providers/quota.py`（开发A 编写）：

```python
from dataclasses import dataclass, field
from typing import Optional

SOURCE_OK = "官方"
SOURCE_UNAVAILABLE = "不可用"

@dataclass
class WindowUsage:
    label: str                 # "5小时" / "本周" / "本月"
    used: float
    limit: float
    currency: str = "USD"

@dataclass
class Quota:
    provider: str                    # deepseek|openrouter|opencode_go
    billing_type: str                # balance|subscription
    currency: str = "USD"
    value: Optional[float] = None    # balance: 剩余余额
    used: Optional[float] = None     # balance: 已用
    total: Optional[float] = None    # balance: 总量
    windows: list = field(default_factory=list)   # subscription: [WindowUsage,...]
    fetched_at: Optional[str] = None # ISO 时间戳
    source_status: str = SOURCE_OK   # SOURCE_OK | SOURCE_UNAVAILABLE
    error: Optional[str] = None      # 失败原因/不可用原因
    refresh_failed: bool = False     # 本次刷新失败但沿用上次官方数据
```

## 5. 接口契约（并行开发统一遵守）

- `providers/<name>.py` 每个实现：`def fetch_quota(cfg: dict) -> Quota`。cfg = config.yaml 中该 provider 的 dict（含 api_key / base_url / proxy，opencode_go 另有 cookie / usage_url）。
- 每个 provider 模块独立可跑：`python -m providers.deepseek` 等。为不依赖开发C 的 config.py，模块 `__main__` 里做 3 行内联 yaml 读取（读项目根 config.yaml 的对应 provider 段）。
- 项目根：项目根目录（仓库克隆目录）。模块内用 `Path(__file__).resolve().parents[1]` 定位。
- `scheduler.QuotaStore`（开发C）：
  - `refresh_all()`：后台异步刷新全部 provider
  - `refresh_now()`：同步强制刷新（打开窗口时用；内部加锁防并发）
  - `quotas` → `{provider: Quota}`
  - `next_refresh_at` → epoch 秒（下次后台刷新时间）
  - 失败时保留该 provider 最近一次官方数据，副本标 `refresh_failed=True` 且更新 fetched_at
- `dashboard_ui/window.py`：`show_window(store, config)` 开新线程建 tk 窗口 → 先 `store.refresh_now()` → 渲染。
- `dashboard_ui/tray.py`：`run_tray(store, config)` pystray 常驻，左键激活开窗，右键菜单=显示窗口/退出（**无"立即刷新"项**）。
- `main.py`（开发C）：装配 config → store → scheduler → tray；干净退出；支持 `python main.py --selftest`（跑一轮刷新打印结果后退出，便于无界面验证）。
- `dashboard_ui/server.py`：`start_server(store, config)` 启动本地 HTTP 仪表盘，**统一默认端口 `127.0.0.1:8787`**（见 README「端口 / Port」一节；可用 `config.yaml` 的 `dashboard_port` 或环境变量 `API_QUOTA_PORT` 覆盖；端口被占用时自动退回系统空闲端口并打印提示，不崩溃）。

## 6. 技术选型（实测依据）

- 窗口：**tkinter**（stdlib）。依据：仪表盘需"开窗→关窗→再开"反复循环，pywebview 的 `webview.start()` 单次启动限制与此直接冲突；tkinter 无 WebView2 运行时依赖、启动毫秒级、三卡+进度条渲染足够。pystray 0.19.5 / Pillow 12.2 / tkinter 已在本机就绪（Python 3.11.9）。
- 托盘：pystray 0.19.5（已装）。
- 依赖：pystray, Pillow, requests, PyYAML（tkinter 为 stdlib）。requirements.txt 已由架构师写好。

## 7. 硬约束（全员遵守）

1. **数据真实性铁律**：所有展示数据必须直接来自供应商官方源（官方 API 或官方登录态页面）；禁止用本地端口/路由/代理日志推算余量；官方无接口就如实显示"官方数据源不可用"。
2. 只读集成本机代理配置，**禁止改动/重启/干扰**任何本地基础设施。
3. key 明文在 config.yaml（已 .gitignore）；界面不打印完整 key。
4. 每步实测不攒批：模块写完立刻真跑验证。
5. 代码简单优先、效果优先，不过度设计。
